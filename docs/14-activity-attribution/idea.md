# 阶段 14 · Agent 操作来源与任务生命周期记录 — Idea

> 状态：**设计已确认，代码与自动化验收已完成，macOS 界面人工验收待完成**（2026-10-23）。这里只记录产品裁决，实施现状与验证记录见 [proposal.md](proposal.md)。

## 为什么做

Pata 已提供本机 MCP，Agent 可以创建 Task、Note 并追加 Activity。随着 Pata 开始由「我」和 Agent 共同使用，只看任务与评论内容，已经不能直观看出谁执行了哪次操作。

用户希望**在记录发生的位置看到来源**，而不是在任务标题、任务列表里堆满机器人徽标。任务「创建、完成、重新打开」本来就是有意义的历史事件；阶段 13 已统一 Today / Task 的 Activity 展示，阶段 14 在此基础上补齐任务创建事件与来源语义。

## 已确认的产品裁决

1. **只区分「我」和「Agent」**。由 GUI 执行的操作显示「我」；通过 Pata MCP 执行的操作显示「Agent」。暂不区分不同模型、Agent 名称、账号或设备；这里的「Agent」指调用通道，不是不可伪造的身份认证。
2. **默认是我，只有 Agent 才存标识**。没有来源字段的全部既有数据按「我」展示；不用 `unknown`、`legacy`、批量回填或历史迁移代码。GUI 新写入也不增加冗余的 `human` 字段。
3. **任务标题区域保持原样**。不在任务标题下方或右侧增加来源徽标；Task 列表、Notes 列表暂不显示来源。
4. **创建也是任务时间线事件**。基于 Task 原有 `created_at` 与创建来源，在 Task 详情、对应日期的 Today 记录里显示「由我创建 / 由 Agent 创建」；不再物理追加一条内容重复的普通 Activity。
5. **完成、重新打开保留既有事件机制**。继续使用 `status_events`，为每次状态变化保存独立来源，展示「由我完成 / 由 Agent 完成」「由我重新打开 / 由 Agent 重新打开」。在 Task 与 Today 维持单行、只读的系统事件。
6. **普通 Activity 来源归属于每条记录**。Task 评论及 Today 独立记录在时间旁以低对比度 Lucide 图标和「我 / Agent」文字展示；同一 Activity 在不同视图来源一致，仍可以按原有规则编辑。
7. **Note 仅展示创建来源**。在 Note 编辑页标题附近提供轻量元信息；不为 Note 添加 Activity 时间线。用户发起的 MP3 转写归为 GUI 操作，不因为调用云端 ASR 就标为 Agent。
8. **只追踪创建或该次事件的执行来源，不追踪最后修改人**。例如 Agent 创建的 Task 后来由我改标题，创建事件仍是「由 Agent 创建」；人工编辑 Agent 评论，也不改写其创建来源。
9. **入口决定来源，调用方不能冒名**。GUI 与 MCP 走同一 Pata Core，Core 使用受信任的调用入口赋予来源；不在对外工具/GUI 输入里开放随意填写来源字段。
10. **Less is More**：不新增主导航、头像、彩色徽标、完整审计日志、修改历史、来源筛选或独立事件实体；不修改现有任务列表排版。

## 预期的阅读效果

任务详情和 Today 的任务事件在原有时间线中自然混排：

- `09:20 · [用户图标] 由我创建`
- `10:15 · [机器人图标] 由 Agent 完成`
- `11:40 · [用户图标] 由我重新打开`
- `12:05 · [机器人图标] Agent`，下一行显示 Activity 评论正文。

图标与文字保持灰色、克制，沿用阶段 13 的时间排版；Today 中仍保留任务标题链接，避免同一条事件脱离任务上下文。

## 本阶段交付的能力

- Task 创建、完成、重开事件统一出现在 Task 详情与 Today 的 Activity 时间线。
- Task、Note、普通 Activity 及任务状态事件可准确保留 MCP 来源；缺省来源始终是「我」。
- MCP 增加受控的任务完成/重新打开操作，使 Agent 不仅能创建任务，也能真正改变任务状态并留下来源。
- 不改变 Markdown 本地优先、单 Core 写入与不复制 Activity 的基础约束。
