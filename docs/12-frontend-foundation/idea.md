# 阶段 12 · 前端基础设施与设计系统整理 — Idea

## 为什么做

Pata 已有明确的 Today / Tasks / Notes 体验，现有 React + Tailwind 界面不需要重新设计；但基础按钮、菜单、弹窗、样式与动效在各业务页面中重复实现，给后续 Agent 开发带来风格偏移和维护负担。

本阶段以 **Less is More / Local First** 为约束，收敛工程实现、而非增加产品功能。

## 已确认的产品裁决（2026-10-21）

1. **保留现有视觉，局部优化。** 维持导航结构、页面密度、卡片组织、三栏关系、Notes 单列与全主区编辑；禁止为了套用组件主题而大面积重新设计界面。
2. **macOS 系统强调色优先。** 交互选中态、焦点和主要操作优先跟随系统强调色；品牌绿主要用于 Pata 品牌识别，成功 / 警告 / 错误保持各自语义。必须实机确认 WKWebView 系统颜色能力，不把固定颜色误称为系统跟随。

## 交付价值

- **对用户**：界面仍然是熟悉的 Pata，但常用控件、键盘操作、拖拽与反馈更一致、更顺畅。
- **对 Agent**：未来开发优先复用统一的组件、变量与既有实现，不每次重新创造按钮、弹层和交互模式。
- **对维护**：减少重复实现与功能重叠依赖，保留组件源码控制权，避免一次性重构风险。

## 本阶段应交付

1. 与既有视觉相容的小型 Design Tokens（颜色语义、字体与排版、间距/圆角、交互状态、层级及动效约束）。
2. 对真实重复点按需整理可复用基础组件；以 shadcn/ui **Nova 作为风格参考**，不全局应用覆盖预设。
3. 统一图标、弹层/焦点、失败反馈等交互实现；定位并改善 Today dnd-kit 拖拽的实际手感。
4. 在 `AGENTS.md` 写入跨阶段长期规则，阶段细节以 [proposal.md](proposal.md) 为准。
5. 按 macOS 实机体验和关键业务回归完成验收，而不是以“库已经安装”作为完成标准。

## 不做

- 不变更 Today / Tasks / Notes 产品信息架构，不添加新主入口。
- 不做整页换肤、不做全量 CSS/组件迁移、不为了统一而重写已稳定的 Logo 动画或 Vditor 编辑器。
- 不预装所有 shadcn/ui 组件，不建设组件展示网站/Storybook。
- 不强制引入 Motion、Zustand 或 react-resizable-panels；没有明确使用场景就不新增依赖。
- 不改变 Go Core、Markdown Schema、业务数据、任务状态与交互语义。
- 不增加可配置字体、强调色或 UI 密度的设置入口。

## 成功标准

**用户感觉 Pata 更一致、更顺手；开发者/Agent 更少重复造轮子；用户没有被迫重新学习 Pata。**
