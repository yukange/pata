# Proposal — 阶段 4：完成文档沉淀链路

## 实施顺序

1. 扫描 Vault 中的 Note，生成标题、摘要、更新时间的单列卡片。
2. 点击卡片进入占满主内容区的编辑器，返回后保留列表搜索/筛选与滚动位置。
3. 集成 Vditor，验证 Markdown 源码往返一致、代码块、表格、中文以及相对链接。
4. 对结构化 Frontmatter 与正文分别处理，避免视觉编辑器覆盖元数据。
5. Task 详情可显式关联 Note；相同标签不能视为关联。

## 本阶段完成标准

- [x] Notes 绝不出现三列嵌套布局。（单列卡片+全主区域编辑器，P4-R1/R2 逐项确认）
- [x] 可以创建、保存、重新打开正常 Markdown 长文；编辑自动保存（防抖+flush，冲突时停止并提示，不丢稿、不覆盖外部内容）。（D19；数据丢失三路径已封堵，关窗 ≤0.5s 窗口为已知 shortcut）
- [x] 外部文件的未保存冲突可被识别，不默默覆盖。（冲突停自动保存+确认式重载+复制草稿）
- [x] Task 可关联 Note，不需要为了写 Note 创建 Task。（note_ids 显式选择器，同标签≠关联有断言）
- [x] 周报、月报和会议纪要只是普通 Note。（无特殊类型分支）

## Notes 行为设计

## 浏览

Flomo 启发的**单列卡片列表**：标题、两行摘要、标签、修改时间；按最近修改排序。搜索与标签过滤保留。无常驻第二层笔记侧边栏。

## 编辑

点击卡片后，主内容区域整体切换为编辑器；全宽写作，左上返回列表（保存过滤条件和滚动位置）。快捷命令搜索可跳转笔记。编辑器优先 Vditor 所见即所得模式，必须验证 Markdown round-trip；可考虑提供源码模式但不列为 MVP 必须。

**自动保存（D19）**：编辑过程防抖自动落盘（停笔约 0.5 秒后写入；原定 1.5 秒，2026-10-12 调低以缩小关窗丢稿窗口），切换笔记或退出时 flush 未保存改动，不丢稿；无实际变更不写盘。遇到外部修改冲突时停止自动保存并提示，由用户选择重新加载，绝不自动覆盖外部内容。

## 内容

架构/POC 文档、会议纪要、周/月复盘、成果记录都为普通 Note。标签可选，标题必填；如果 Markdown 正文首行 `# 标题` 与 Frontmatter 标题一致，UI 可在显示时折叠重复标题，但不得删改正文源数据；可以和 Task 显式关联，也可完全独立。

## 标签

标签区域在**全局侧栏**，点击进入统一聚合视图，不在 Notes 内嵌另一列标签列表。点击 Notes 主入口时始终回到笔记列表。

## 后续改进：统一 Note / Task 标签编辑（已实施）

> 这是阶段 4 的后续交互改进，不重开已完成的阶段 4 验收，也不另立阶段 12。仅调整标签编辑与数据保护行为；Markdown Schema 仍使用原有 `tags: string[]`，不新增标签实体或管理页。

### 当前问题

- Note 编辑器以逗号拼接/拆分整组标签，既未复用 Task 的大小写不敏感去重，又会将原本含逗号的合法标签误拆分，导致正文等其他字段保存时也可能改写 `tags`。
- 编辑中每次按键均触发自动保存，Enter 与 Escape 都只是关闭输入框，Escape 无法取消未确认的编辑。
- 含非法 `#` 的标签进入通用保存流程后才被后端 Schema 拒绝，缺乏就近反馈。
- 冲突后的「复制草稿」只包含标题和正文，漏掉未保存的标签修改。

### 交互与实现原则

1. Note 编辑器改为**独立 Tag Chip + 单个新增输入框**：Chip 上可直接删除，新增时可选择已有全局标签或输入新名称；不再通过编辑逗号分隔的整串文本增删标签。不新增常驻面板。
2. Note 和 Task 尽量复用轻量标签输入组件、候选逻辑及纯函数规范化/校验；不要形成两套标签语义。共享行为不应强迫两者重构无关的保存流程。
3. 标签内部仍是不带 `#` 的自由字符串；首尾去空白、允许开头输入 `#` 时去掉前缀、拒绝内部 `#` 与空标签；按大小写不敏感语义去重，**保留首次采用的显示大小写**。逗号是标签文本的合法字符，不是数据分隔符；不要额外引入层级或强制小写规则。
4. 单个新增输入框中，Enter 或点击候选/确认按钮才提交标签；Escape 只放弃**当前尚未提交的输入**并关闭输入框，不能撤销之前已确认并保存的增删。输入法组合期间不得误提交。失焦关闭输入时不隐式创建标签。
5. 标签加入或移除后继续走现有 Note 自动保存（防抖与离开 flush），但新增输入框中尚未确认的字符不属于 `tags`，不能触发写盘。无实际标签变化不写盘；保存失败/冲突时保留已编辑的标签及错误提示。
6. 冲突保护的「复制草稿」必须完整保留标题、标签和正文，保证重新加载前可恢复所有本地改动；不得用标签编辑绕过原有基线校验和冲突机制。

### 验收补充

- [x] Note 与 Task 的添加、移除、已有标签建议及去重规则一致；`Pata`、`pata` 不会成为两个标签。
- [x] 从磁盘读到单个 `研发,平台` 标签，打开、编辑正文、保存和重新打开后仍为**一个**标签；含中文逗号的情况同理。
- [x] Enter 确认、Escape 取消未提交输入、输入法确认、失焦关闭和空标签均按约定行为工作；已提交的添加/删除正常自动保存。
- [x] 输入非法标签能在标签区域直接提示，不会导致整篇 Note 的自动保存反复失败。
- [x] 发生外部写入冲突时不会覆盖磁盘；「复制草稿」包含本地标签变更，重载前可恢复。
- [x] 普通 Note 和只读音频逐字稿 Note 都可以修改标题/标签而不误改正文；全局标签聚合和搜索正常刷新。

## 限制

无页面层级、数据库属性系统、双向链接图谱、所见即所得块编辑器等。

## Notes 代码块与撤销（2026-10-22 修正）

原生界面复现了代码块源码与预览同时显示为两块背景，以及在 Vditor 默认 800 毫秒历史防抖结束前按 `⌘Z` 无效的情况。临时笔记的下方段落仍保留，未复现正文被删除。

- 代码块编辑时只显示源码，离开后显示语法高亮预览；代码块间距不作用于 IR 隐藏源码，深浅色均保持正文可读。
- 优先复用 Vditor 原生历史栈与快捷键机制，撤下私有方法覆写与外部按键拦截；通过官方 `undoDelay: 100` 将入栈防抖由 800ms 降至 100ms，减少快速编辑时的未入栈窗口。
- 快捷键与正文编辑沿用 Vditor 原生事件处理，最终正文继续走既有自动保存、引用和冲突保护。

- [x] 原生验证转换后立即撤销、重做、代码输入的连续撤销重做，以及撤销后新编辑使旧重做失效；标题输入框保留原生撤销。

## Notes 输入提示（2026-10-29 修正）

- 输入 `:` 或后续 emoji 名称时不弹出 emoji 候选，冒号正常作为正文输入。
- 保留 Vditor 默认工具栏功能，使用官方 `toolbarConfig.hide` 与已有 CSS 隐藏外观，不将 `toolbar` 清空。`hide` 本身会在悬停时展开，完全不显示工具栏采用[维护者建议的 CSS 方式](https://github.com/Vanessa219/vditor/issues/1847#issuecomment-3228345694)。

- Vditor 4.0.0 的公开 `hint` 配置没有关闭 emoji 触发的开关，且会无条件追加 `:` 触发器；仅这一处在 `after` 中清空实例的 `hint.extend`，已用 `shortcut:` 标注，待上游提供开关后替换。不能将这一行兼容处理描述为官方推荐配置。
- 没有笔记候选时不拦截原生键盘处理；既有 `[[` 笔记/文件候选继续保留输入法组合保护。
