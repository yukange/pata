# 阶段 16 · Notes 左右分栏与草稿体验 — Proposal

> 状态：**代码与自动化测试已完成，待 macOS 实机走查**（2026-10-26）。已确认的产品取舍见 [idea.md](idea.md)。本文件是 016 的实施与验收主文档；**当前已生效的 Markdown Schema 仍以 [阶段 2](../02-foundation/schema.md) 为准**，在实现本阶段数据变更时同步更新权威 Schema，禁止仅靠本 proposal 宣称新协议已上线。

## 一、现状与目标

- 现有 `frontend/src/NotesView.tsx` 在卡片列表和全区域编辑器之间二选一渲染，已有 `ListNotes`、选中 Note ID、编辑器自动保存/冲突保护、Vditor、引用跳转、逐字稿与删除能力。
- 目前编辑器新建/更新分支要求非空标题才可保存，`isNewDraft` 表示尚未持久化的临时编辑态，**不能直接拿来表示本阶段持久化的「草稿」**。
- `App.tsx` 已有全局导航、唯一 Task Inspector 和打开 Note 的路由入口；`SearchOverlay.tsx` 已能通过 Note ID 打开目标，但关闭时会清空搜索词。
- 目标：将 Notes 工作区改为同屏的**左列表 + 右编辑区**，上草稿/下笔记，采用同一 Note 持久化模型与同一编辑器。

## 二、目标交互（016-001）

### 2.1 Notes 布局

```text
App Shell
├── Navigation               原有 Today / Tasks / Notes
└── Workspace: Notes
    ├── NotesList             草稿（无标题正文预览）/ 笔记（标题）
    └── NoteEditor            当前选中的唯一编辑器
```

- Notes 工作区**内部**是两栏，不创建第二个 Inspector；进入 Notes 时若全局 Task Inspector 展开，则视觉上隐藏它、保留选择和未提交草稿，离开 Notes 后恢复原 Inspector 语义，不能出现导航 + 列表 + 编辑区 + Inspector 四栏。
- 默认列表宽约 280px，建议可调范围 240–400px，拖动分割线必须跟手，无逐格跳跃；存本地视图偏好。可收起并恢复列表，编辑区占剩余空间；窄窗优先隐藏列表，保持编辑器可用。只在必要时复用现有 resize 实现，不引入第二套通用布局框架。
- 右侧只有当前一篇 Note 的 Vditor（逐字稿则沿用只读视图）；切换左侧项不导航至全屏编辑页，不要求返回列表按钮。左右两栏独立滚动；不要因正文输入导致列表抖动或丢失滚动位置。
- 初次无选中 Note 显示简洁空态，不自动创建草稿；以后进入 Notes 恢复上次选中的有效 ID，已删除/无效则退回空态。避免全局标签/搜索导航造成用户草稿丢失。
- 列表默认上「草稿」、下「笔记」，分组独立折叠并保留界面偏好；空草稿分组仍保留创建入口。草稿展示正文开头最多两行（去除 Markdown 语法的可读预览，不能误把首行存成标题），不展示标签与时间；正式笔记只展示标题，不展示摘要。选中项仅用统一高亮表现，不叠加来源/临时状态徽标。

### 2.2 新建与编辑

- Notes 主「+」**默认新建草稿**：直接聚焦右侧正文，不强制输入标题。下拉菜单含「新建笔记」及「从音频创建逐字稿」，不重复出现等价的「新建空白笔记」。草稿组标题右侧 `+` 也可直接新建草稿，复用同一方法。
- 草稿编辑时不渲染 title、tags、创建来源/时间等元信息，也不显示普通的「已保存」状态；只有保存中必要反馈及失败/冲突提示。复用现有 Vditor、文件插入/链接、自动保存和离开保护。
- 新草稿**首次有非空内容时**创建实际 Note（稳定 ID），没有输入就离开则不留空文件；已保存草稿正文被清空后仍保留，直到用户主动删除。草稿有内容不要求标题。首次落盘后沿用当前编辑器，不重新加载正文，保留焦点、代码块光标和保存期间继续输入的内容。
- 正式笔记保留现有标题和可选标签编辑、自动保存、`created_by` 显示与逐字稿能力。音频导入仍直接生成正式 Note，不经过草稿。

### 2.3 草稿原地转为笔记（016-002）

```text
草稿（只有 Markdown 正文）
   └─ 点击「转为笔记」
       └─ 右侧原地显示正式 Note 的标题、标签与原正文
           └─ 标题 input 挂载后立即 focus
               ├─ 非空标题 + 自动保存成功 → 同一 Note 从草稿组移入笔记组
               └─ 标题仍为空 / 离开 / 保存失败 → 仍是草稿，正文保持不变
```

- **无弹窗、无确认按钮、无复制、无路由跳转**。点击操作仅进入「正在命名」的局部 UI 状态；只有非空标题被成功持久化后才真正改变 `draft`。正在命名时不要提前从草稿组移走或让列表来回闪烁。
- 标题输入框直接获得焦点，使用 React ref 和挂载后的 focus；中文输入法组合期间不进行转换提交或错误的失焦处理。标题输入后沿用自动保存防抖；可选标签在正式 Note UI 显示后可以编辑，但提交前不能生成一份独立的「正式 Note」。
- 转换成功后，**Note ID、原路径、创建时间、正文、附件链接、引用绑定、`created_by` 均原样保留**；不生成新文件或改名、不将 Markdown 正文第一行自动提升为标题。仅保存新标题、可选标签、`draft` 状态和修改时间。成功后在正式笔记组中选中同一篇，右编辑器保持原地。
- 转换失败或外部编辑冲突时维持草稿与用户已经输入的标题/正文，保留重试空间，不能半转换、覆盖正文或静默丢失输入。正式笔记**不存在**「退回草稿」菜单或快捷键。

## 三、数据协议与 Core（016-003）

### 3.1 拟新增的 Note 字段

本段为本阶段**目标协议**；实现时同步更新 `docs/02-foundation/schema.md`（当前生效协议单一来源），且保留旧数据兼容规则：

```yaml
---
type: note
id: n-01xxxx
draft: true
created_at: 2026-10-26T18:30:00+08:00
updated_at: 2026-10-26T18:45:00+08:00
---

直接开始编写 Markdown。
```

- 仅显式 `draft: true` 代表草稿；缺省/`false` 均视为原有正式 Note。**绝不能因为文件缺少 title 就自动推断为草稿**，以免误分组 Vault 中已有的无 Frontmatter Markdown。
- 草稿的 `title` 可缺失或为空，`tags` 不提供输入/创建时不写入；正式笔记由 Pata 创建/修改时仍要求标题非空，`tags` 可选。需与既有外部原始 Markdown 的解析兼容规则并存，不误拒绝历史笔记。
- `id`、`created_at`、`updated_at` 必须保留用于身份、排序与重扫；`created_by: agent` 仍按阶段 14 的受信任来源机制可选且只能由 Core 赋值，草稿 UI 不展示，转换不覆盖它。
- 草稿与正式笔记都保存在 `notes/`、使用原 Note 读写/索引。新草稿文件名可基于稳定 ID，且**转换时不改路径**；需检查当前 slug 命名/更新逻辑是否会因标题更新而重命名，避免相对 Markdown 链接失效。文件级原子写入、baseline/冲突保护及未知 Frontmatter 字段保留照旧。
- `ListNotes`、`GetNote`、`CreateNote`、`UpdateNote` 和前端 bindings 在实现时拓展草稿字段，不为 Draft 创建平行业务 API/目录/数据副本。

### 3.2 标签与引用

- 草稿**没有标签 UI**，创建草稿不带标签，也不计入标签聚合；转换为正式笔记时用户可选填标签。
- 草稿正文允许现有 Markdown 链接和附件链接，也可以引用**已有正式 Note**；草稿**不作为** Task/Today/其他 Note 中 `[[` 的 Note 候选目标。候选筛选与解析按实际稳定身份校验，**不要把已绑定但失效的历史引用按标题重绑定**。
- 草稿和正式笔记都参与全局全文搜索，草稿结果以正文片段展示，不因无标题丢失命中；搜索/索引不依赖 `title` 非空。
- 不引入草稿引用的专用别名、隐式第一行标题、双向关系、引用自动修复；若已有文件直接含指向草稿的标准相对链接，保守按实际路径处理，不自动删除或改写。

## 四、列表排序与全局搜索（016-004）

### 4.1 排序

- 上下两组**各自**按照 `updated_at DESC, created_at DESC, id ASC` 稳定排序，不提供手动拖拽、置顶或排序设置。
- 编辑中自动保存应刷新内容预览，但**冻结列表项位置**，在用户切换对象、重新进入 Notes 等自然边界重新排序，避免当前条目因每次保存跳至顶部。草稿成功转换则立即从草稿组移入正式分组并选中，属于明确操作例外。
- 折叠状态和列表宽度作为 App 视图偏好保存，不写入 Note Frontmatter。

### 4.2 统一打开目标

- 从全局搜索、Today/Task/Activity 的引用、Note 正文链接打开时，都切换/定位到 Notes 的**同一个**右编辑器，并让左侧对应分组展开、条目滚动可见并选中。对搜索命中的草稿也同样成立。
- 全局搜索浮层关闭后不再立即清空当前关键词/结果；再次 `⌘K` 继续前一次搜索以便查看其他命中。搜索输入仍可直接编辑/清除；无需保留无限搜索历史，也不增加专用的「从搜索返回」编辑页。
- 无需正文命中词精确滚动/高亮（尤其 Vditor 内部光标定位），无 Tab，也不替换 Notes 左侧的完整分类列表为搜索结果。
- 切换页面/Note 前继续使用现有编辑器 flush/确认保护；保存失败、冲突或取消时留在源位置。与 App Shell 全局 Task Inspector 的草稿保护协同，不要为了导航偷换来源实例。

## 六、必须覆盖的回归

1. 创建草稿：直接聚焦正文；有内容后自动保存，首次保存不重建编辑器或丢失代码块焦点，保存期间继续输入的内容随后正常保存；关窗重启、重扫 Vault 后草稿仍在且保留正文；空白未落盘草稿离开后不产生空文件。
2. 同时存在多张草稿时可独立切换，左侧显示最多两行正文摘要且无标题/标签/时间/来源；正式笔记只显示标题。
3. 点击「转为笔记」后**同屏切换 UI 并立即聚焦标题**，无弹窗；中文输入标题和后续标签正常；不填写标题离开仍为草稿；保存失败/冲突不丢正文。
4. 转换成功，左侧由草稿移入笔记组，ID/路径/created_at/created_by/正文/文件相对链接均不变；无反向转换。
5. 草稿及正式 Note 均可全局搜索；从搜索点击，左侧自动展开定位、右侧同一编辑器显示；重新 `⌘K` 能复用上次关键词与结果。
6. 草稿不出现在 `[[` Note 目标候选中，却可主动链接正式 Note 与附件；既有同名/失效 ID 绑定规则不回退。
7. 持续输入自动保存不会引起列表不断跳位；自然切换后按更新时间重新排序；折叠、宽度和窄窗口行为一致。
8. 从任务详情/Today 打开 Note、返回或切换其他页面时，任务 Inspector 与编辑草稿不丢；保持正式笔记和 MP3 逐字稿既有 UI、只读/音频时间戳行为。
9. 删除草稿/笔记不级联删除 `files/` 资源；异常文件仍遵守现有单文件隔离和可恢复机制。

## 七、不做

独立 Draft 实体/目录、正式笔记转回草稿、草稿标签或标题、转化弹窗、Tab/分屏编辑器、独立速记窗口、手动排序/置顶、自动整理/过期、正文搜索命中位置跳转、全局数据迁移、无关框架换代。
