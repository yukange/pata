# 阶段 15 · 应用内更新与 macOS 原生菜单 — Idea

> 状态：**设计已确认，待实施**（2026-10-24）。本文件记录产品裁决；实现与验收范围见 [proposal.md](proposal.md)。

## 为什么做

Pata 目前主要通过本地构建与手动安装更新。希望获得类似 ChatGPT / Magpie 的桌面更新体验：应用自动发现新版本，入口就在侧边栏底部的设置旁，点击即可下载，进度直接体现在按钮上，不再要求手动下载 DMG。

同时补齐 macOS 屏幕顶部左上角的 **Pata 应用菜单**中的「设置…」「检查更新…」，与既有主窗口设置入口共用同一行为。

## 已确认的产品裁决

1. **设置页增加唯一的「自动检查更新」开关**，官方正式安装版默认开启；启动后检查一次，之后约每 6 小时检查。关闭后不再后台请求或主动显示尚未开始的更新提示；用户仍可通过「检查更新」手动触发。网络失败静默，主动检查失败才轻量反馈。**开关不是「自动下载/自动安装」**，无论开启与否都只能由用户点击「更新」开始下载。
2. **仅发现新版本时显示更新按钮**，放在左侧边栏底部、设置按钮旁边；默认隐藏，不新增主导航或更新中心。现有 Vault 健康异常入口仍须保留。
3. **点击「更新」直接开始下载**。不显示更新版本/说明弹窗，不再要求「查看版本」这一额外操作；下载百分比和进度指示在**同一个按钮内**实时变化，风格参考 Magpie。
4. **只展示真实下载百分比**（已下载字节 / 总字节），不能把校验、解包、安装伪装为进度百分比。下载至 100% 后短暂校验/暂存不另设「准备安装」按钮状态。
5. **下载、校验和暂存完成后，若没有未保存草稿，直接安装并重启**，无需再点击确认。
6. **有未保存草稿时不能强制重启**。按钮显示「等待安装」；用户继续编辑或先保存/放弃草稿，之后**主动点击「等待安装」**才继续。即使草稿后来自动保存，也不在用户编辑中途自动重启。
7. **失败可重试**，不覆盖仍可运行的旧版本，不破坏当前 Vault；更新不改变 Task/Note/Activity 数据模型或本地优先原则。
8. macOS **左上角原生 Pata 应用菜单**保留系统标准结构，接通「设置…」（⌘,，打开现有主窗口设置页）与「检查更新…」（主动检查并简短反馈）。它与右上角 Pata 菜单栏状态图标是不同入口；本阶段不重做状态图标菜单。
9. **保护开发者自编译构建**：只有来自官方发布流程的正式安装包才可执行应用内自替换更新。开发模式、源码自编译、个人定制/临时签名构建均禁用官方自动检查与安装；不能仅凭当前版本号推断为官方发布版。这样合并别人贡献的代码不会静默替换其开发环境。
10. **Less is More**：仅一个检查开关，不做自动下载/自动安装模式、多更新通道、强制升级、增量补丁、下载详情页、历史版本列表或自研更新引擎。

## 按钮状态

| 时机 | 用户可见按钮 | 行为 |
| --- | --- | --- |
| 无更新 / 静默检查中 | 隐藏 | 后台完成检查 |
| 检测到新版本 | `更新`（下载图标） | 点击立即开始下载 |
| 下载中 | 下载图标 + `XX%`（环形/紧凑进度） | 读取真实下载进度，不另开窗口 |
| 下载完正在校验/暂存 | 延续 `100%` 的短暂忙碌态 | 不显示「准备安装」 |
| 已就绪，且存在未保存草稿 | `等待安装`（时钟图标） | 用户自行保存/放弃后点击继续 |
| 正在触发重启 | `正在更新`（短暂态） | 退出、替换应用并重新打开 |
| 更新失败 | `重试更新` | 允许用户重试，错误可查看 |

**「等待安装」不是底层 Updater 的解包状态**，而是「已经暂存就绪、为保护草稿而延迟重启」的用户态；「准备安装」不作为独立用户态。

## 本阶段交付

- macOS 可直接从应用内更新的签名发布包、GitHub Releases 发布规范和版本管理。
- Wails v3 更新能力接入、一个可持久化的「自动检查更新」开关、正式版/开发版隔离、更新按钮与真实进度、草稿保护及重启。
- 原生 Pata 应用菜单的设置和检查更新操作，与现有窗口交互保持一致。
- 真正从旧安装版本升级到新版本的 macOS 实机验收。

详细技术路径与完成条件以 [proposal.md](proposal.md) 为准。
