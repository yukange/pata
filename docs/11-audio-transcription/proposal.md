# Proposal — 阶段 11：本地 MP3 → Markdown 逐字稿

> **状态：代码实现与验收已完成。** 以前置 [阶段 10](../10-settings/proposal.md) 已完成的 Keychain 凭证为基础，只为现有 Notes 增加只读逐字稿及音频定位能力；阶段 9 的 Files 机制已经具备。全链路测试与验收见 `acceptance_audio_transcript_test.go`。
>
> **唯一数据协议**：Note/文件资源格式遵循 [阶段 2 Schema](../02-foundation/schema.md)；本文件主要规定交互、服务流程和验收。示例是表现形式，不额外定义 JSON 或第二套 Schema。

## 一、产品与交互边界

| 场景 | 目标行为 |
|---|---|
| 新建入口 | Notes 既有新建操作中增加「从音频创建笔记」，不添加「语音转写」一级导航、特殊列表或独立工作台 |
| 未配置 Key | 打开阶段 10 的主窗口设置内「语音转写」，配置后返回当前流程；没有地区/模型选择 |
| 导入文件 | 第一版只接纳本地 MP3；原始文件复制到 `files/`，不修改外部文件；同名不覆盖；**导入成功后立即创建关联 MP3 的普通 Note**，不等待 ASR 成功 |
| 导入后 Note 状态 | 上传中/转写中在当前 Note 内展示；正文在等待、成功、失败各状态都不可直接编辑；失败时保留 Note 和 MP3，由 Note 内入口重试；不得静默生成重复 Note |
| 音频预处理 | 检查声道；仅当说话人分离需要时生成临时单声道副本，不统一强制降到 16kHz/32kbps；原件不变 |
| 任务进行中 | 显示「上传中 / 正在转写 / 正在写入逐字稿」等真实阶段，不伪造无法获知的完成百分比；在同一 App 进程内切换页面不停止任务 |
| 写入 Note | 使用音频导入时已创建的 Markdown Note，成功后填充**只读逐字稿正文**；标题保存于 Note 的既有 title 字段，不在正文重复写 `# 标题`；音频关联不因转写失败消失 |
| 顶部播放器 | 显示关联 MP3、播放暂停、进度条、当前精确时间与总时长；不重画整个 Notes 编辑界面 |
| 点击时间戳 | 精确跳到该句开始时间并播放（实际 seek 误差取决于媒体解码/识别时间戳） |
| 拖动播放器 | 拖动时更新预览时间；**松开后**定位最接近且不晚于该时间的句子，滚动到可视区中部附近并轻微高亮；不移动编辑光标 |
| 正常播放 | 不自动抢滚动位置，不妨碍用户阅读、选择、复制和搜索逐字稿 |
| 重新转写 | 播放器 `···` →「重新转写」；复用原 MP3 与当前固定模型；旧稿在任务成功之前保持可用 |
| 重新转写完成 | 沿用已确认的替换确认流程，替换**整个只读逐字稿正文**，保留 Note 标题、标签及原始 MP3 关联；拒绝/失败则保留旧稿，禁止竞态覆盖或擅自覆盖外部文件改动 |
| App 退出/再次打开 | 不维护跨重启持久 task_id 或后台任务中心；正在执行的请求随 App 退出终止本地等待，重新打开原 Note 后可手动重试/重新转写，MP3 和原 Note 一直保留 |
| 逐字稿只读边界 | **仅自动生成的逐字稿 Note 的正文只读**：不可在 Pata 中编辑、粘贴或插入附件；可选中、复制、搜索、点击时间戳；标题与标签仍可修改。其他普通 Note（即便含 MP3 链接）保持现有完整编辑能力 |

## 二、服务与模型

- 唯一供应商：**阿里云百炼**，唯一模型：`qwen-audio-3.1-asr-flash-filetrans`，唯一地域：**华北 2（北京）**。请求凭证由阶段 10 的 Go Core Keychain 服务读取；前端不持久化明文 Key。
- 使用百炼临时文件上传、异步提交与按 `task_id` 轮询，再获取识别结果；HTTP 请求/轮询要有有界超时、合理重试及可解释的失败信息。重试不能悄悄新建多篇重复 Note。
- 转写时开启说话人分离。官方对分离输入有单声道要求，并建议时长不超过 2 小时；超过建议时长应提前说明风险，但**不自动切换供应商**。
- 临时文件上传模式有大小/时效与稳定性边界，首版可在个人 BYOK 用途下采用：**上传文件最大 1GB**（还需遵守模型限制），临时 `oss://` URL **48 小时有效**，上传与识别需属于同一阿里云主账号；通过 HTTP 使用该临时 URL 时必须带 `X-DashScope-OssResourceResolve: enable`。必须处理上传失败、过期及异步任务失败。源 MP3 永远留在本地 `files/`，云端文件不被当成本地持久引用。
- `qwen-audio-3.1-asr-flash-filetrans` 的任务提交请求**必须携带 `parameters` 对象**（没有参数也要 `{}`）；启用说话人分离时设置相应参数。识别结果 `transcription_url` **24 小时有效**，成功后应尽快读取并转换到已有本地 Note；绝不把临时云端结果 URL 当成持久数据。
- **域名决策保持克制**：北京旧 DashScope 域名当前不要求 Workspace ID，新业务空间专属域名需要用户自身的 Workspace ID。阶段 11 先实测固定模型在无需 Workspace ID 的北京旧域名上是否可用；如不满足，再基于该个人应用的实际业务空间确定专属域名，不为此提前增加 UI 设置，也不能把任意人的 Workspace ID 假定为通用常量。
- 使用 BYOK 并由用户主动触发「从音频创建笔记」时，不额外增加「是否同意上传音频」隐私确认弹窗，也不增加对应隐私设置开关；如调用失败正常提示即可。
- 如果需要热词与领域上下文增强，可以在内部使用合理请求参数；**不增加用户可配置的热词/模型/方言页面**。识别准确性及 speaker/time 行为以真实会议样本验收，不把调研文档中的夹具评分当作已通过验收。
- 音频 API JSON 只在处理时存在于内存或临时请求生命周期；不持久化 `transcript.json`、`metadata.json`、DB 记录或云端转写历史。

### 异步任务的简化生命周期

1. 用户选定 MP3 并成功复制进 `files/` 后，**立即创建 Note** 并确定与原音频的关联；不等转写成功再生成笔记，也不建立第四类业务实体。
2. Go Core 异步提交与轮询。用户切换 Today/Tasks/其他 Note 时，任务在当前 App 进程内继续；完成后基于 Note 最新版本进行安全写入。**Pata 内生成逐字稿的正文始终只读**，但仍须保护外部编辑器引入的竞争修改，并保留期间发生的标题/标签变更。用户重新返回原 Note 时查看最终内容或失败提示。
3. 失败、请求超时或取消后保留 Note + MP3。尚无逐字稿的 Note 通过播放器菜单中的「开始转写 / 重试转写」操作再次尝试；已有逐字稿的 Note 使用「重新转写」；避免单独任务列表或转写状态数据库。
4. 关闭 App 不保证异步任务继续或重启后自动找回服务端任务。重新打开时，即使只剩含 MP3 关联的空白/草稿 Note，仍能手动发起转写；不能因为失去内存状态而将其视作损坏笔记。
5. 用户不能在 Pata 内修改生成逐字稿的正文，但可能在转写期间修改 Note 的标题、标签，或由外部工具修改其 Markdown 文件。因此写入识别结果时只更新目标正文并保留最新合法元信息，遇到外部竞争编辑遵循既有冲突保护，不允许旧快照无提示覆盖。只持久化已有 MP3 与 Note 文件，不新增 JSON 侧车/WAL。

## 三、原始 MP3、Note 与 Markdown 的关系

- 原始音频落在 `files/`，由现有阶段 9 文件复制、安全命名、Vault 内路径解析和文件引用能力管理；**不删除有可能被多个 Note 引用的音频**。
- 逐字稿落在 `notes/` 下，仍是 Markdown Note 文件：保留 Notes 单列列表、标题、标签、全局搜索与普通导航，但**自动生成的逐字稿正文仅以只读方式呈现**，不提供正文编辑。标题/标签沿用现有编辑能力，不增加 `type: transcript` 或独立 Transcript Entity。
- Note 与原始 MP3 必须建立**明确且唯一的主录音关联**，仍采用 Vault 内相对路径，不写死 `../files/`；是复用正文标准 Markdown 文件引用，还是将主录音路径保存在 Note Frontmatter，**目前待最终确认**。正文其他 MP3/文件链接无论如何都不应自动抢占主录音身份。音频不存在或被移动时保留 Note 并提示关联失效。
- Markdown 按句子保留毫秒级时间。**Note 标题保存在现有 `title` 字段**，正文不重复插入 `# 技术架构讨论`。以下只表示时间戳与发言排版，**尚不冻结音频关联和时间戳链接的最终 Markdown 语法**：

  ```markdown
  [00:01:05.230] 说话人 1

  我们先讨论一下这次技术架构的调整。

  [00:01:18.760] 说话人 2

  我觉得可以先把现有的方案简化一下。
  ```

- **待确认设计**：时间戳可用可点击的 Markdown 链接承载，降低自定义点击文本解析难度；主录音关联倾向保存在 Note Frontmatter，避免正文插入额外 MP3 链接。必须明确区分“自动生成的只读逐字稿”与“含普通音频附件的可编辑 Note”，不能仅凭有 MP3 链接就锁定正文。最终字段/链接格式先纳入 [阶段 2 Schema](../02-foundation/schema.md)，不在本文临时创建第二套协议。

- 时间戳语义为音频**起点时间**；从 API 毫秒值格式化为 `HH:MM:SS.mmm`，不得截断为秒。说话人名称由识别结果映射为一致的「说话人 1/2…」，不要求真人身份信息。
- **只读语义仅针对 App UI**：自动生成的逐字稿不允许修改发言内容、说话人和时间戳；仍可选择、复制、搜索，时间戳呈现为可点击的播放定位链接。底层 Markdown 文件仍由用户持有，外部工具可能修改它，读取时对非法/缺失时间戳按普通文本显示，不能破坏或强行重写原文件。普通手写 Note 的编辑行为完全不变。
- Note 的关联音频识别与内存时间索引可从现有 Markdown 重建，不引入持久时间索引。若实现需要额外轻量 Note 元信息，必须先更新 [Schema](../02-foundation/schema.md)，并保持 Note 仍是普通 Note；不得在本文件另立协议。

## 四、播放器与逐字稿定位

- 音频增强 UI 和正文只读模式**仅**应用于自动生成的逐字稿 Note：必须能以稳定、明确的关联标记识别，不能把普通用户手动插入 MP3 的 Note 错误锁定。原始音频丢失时允许查看/复制逐字稿，仅播放功能报错；其他普通 Note 的编辑和预览不变。
- 顶部播放器保持轻量，复用系统媒体播放能力。精确显示 `HH:MM:SS.mmm` 的当前进度，时间值在毫秒单位处理，不因 UI 格式化导致秒级定位。
- 点击正文时间戳：通过只读 Markdown 链接 seek 至对应音频位置并开始播放；无需在可编辑 Vditor 内容中劫持光标，正常的文本选择与复制仍应工作。
- 拖动进度：松开（或键盘 Seek 提交）时用时间索引定位对应句子并滚动，高亮只作短暂视觉反馈。实现可按开始时间排序、二分查找；跨句时间空隙优先定位最近前一句，超边界作首尾裁剪。
- **正常播放不持续自动滚动**；用户手动滚动、选择和复制时不受播放时间驱动。不要把每句话做成聊天气泡、独立卡片或一列密集分割线。

## 五、重新转写与失败恢复

- 唯一入口为播放器 `···` 的「重新转写」。不提供供应商选择、模型选择、自动转写历史、复杂差异视图。
- 原 MP3 从本地 Vault 读取，按同一链路生成新的**候选**逐字稿；结果成功前不写入现有 Note 正文。若原 Note 还没有逐字稿，操作文字可为「开始转写 / 重试转写」，与已有逐字稿的「重新转写」复用同一处理流程。
- 既有约定暂保留“转写完成后确认是否替换旧稿”的轻量确认操作；当前 Pata 内不允许用户编辑逐字稿，因此无需显示保护人工备注的特殊文案。按钮可为「保留原稿 / 替换逐字稿」；不做差异对比和版本历史。
- 用户确认替换后，基于 Note **最新内容**和已有保存冲突保护进行安全更新；标题、标签等元信息变更和外部文件竞争修改不得被旧快照覆盖。
- **替换范围统一为整篇只读逐字稿正文**，不试图区分句子或做局部内容合并；**标题、标签、原始 MP3 关联及其他合法 Note 元信息保留**。虽然正文在 Pata 内只读，确认前仍应检查是否存在外部文件修改，避免确认对象已过期。
- 转写失败、上传中断、Key 无效、音频失效、用户拒绝替换时，原 Markdown 和原 MP3 不变。允许用户再次发起，不要求任务中心/自动恢复队列。

## 六、实施顺序

### P11-001 — MP3 导入与异步转写

- Notes 新建菜单增加「从音频创建笔记」及缺 Key 设置引导；复用阶段 9 的文件导入、Vault 安全路径和 Note 创建 API。**成功导入 MP3 后先创建关联的 Note**，然后启动异步识别，不等待结果才建 Note。
- 用 App Core 实现声道检查/必要的临时转码、临时上传、异步提交、轮询、下载、异常处理；用阶段 10 Keychain 配置。
- 成功时向已有 Note 填入句子级毫秒时间戳与说话人文本，Note 的 `title` 不在正文重复；失败时可以从相同 Note 重试。音频关联最终表示形式待确认后更新唯一 Schema；原文件始终可回听。

### P11-002 — 播放器与双向时间定位

- Note 顶部轻量播放器；逐字稿正文使用可选择/复制的只读 Markdown 展示，毫秒级时间戳可点击；具体链接语法待确定并写入统一 Schema。
- seek → 逐字稿滚动/高亮；逐字稿时间戳点击 → 进度定位并开始播放；自然播放不夺取滚动控制。
- 确保键盘与滚动容器可用，逐字稿不能获取正文编辑光标；普通 Note 的 Vditor 编辑与自动保存、Notes 单列列表不回退。

### P11-003 — 重新转写、边界处理与验收

- 播放器 `···` 提供重新转写（无逐字稿时为开始/重试转写）；成功后按现有约定确认是否替换**整个只读逐字稿正文**，保留原始音频关联与 Note 属性，失败/拒绝均保留内容。
- 覆盖错误、时长提示、无效文件、Keychain 读取失败、网络超时、异常 API 结果和被移动音频文件。
- 测试 Go 服务、前端构建及 macOS 真机 GUI；用真实多人中文/中英技术会议样本核对词汇、说话人一致性、毫秒时间跳转及长时录音。
