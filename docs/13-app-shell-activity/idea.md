# 阶段 13 · App Shell 与 Activity 体验统一 — Idea

> 状态：**规划确定，实施中**（2026-10-21）。阶段 12 已完成并冻结，本阶段是新增独立交付阶段，不回写 012 的已验收范围。

## 为什么做

Pata 最初确定的桌面体验是**一个应用级三栏框架**：左侧导航、中间工作区、右侧按需打开的任务详情。此前 Agent 实现成了 Today / Tasks / Tag 分别持有右侧详情容器，导致应用布局的责任错误地落在页面内部，详情宽度又固定为 400px。用户明确裁决：**恢复原本三栏架构，不以“少改代码”为理由保留偏差**。

同时，Activity 在 Today 和 Task 详情的展示、编辑、输入样式不一致：Today 有原地编辑，Task 详情没有；Today 输入框与发送按钮分离，Task 已采用一体式 Composer；两处 Activity 的时间与内容排版也不同。

因此 013 同时收敛**布局架构**与**Activity 交互**，两条工作流在同一阶段交付、分批 PR 实施与验收。

## 已确认的产品裁决

1. **三栏属于 App Shell**：左侧 Navigation 常驻，中间 Workspace 由 Today / Tasks / Notes / Tag 使用，右侧 Inspector 全局唯一、可收起。Tag 是导航中标签筛选的内容视图，**不新增第四个主导航**。
2. **右栏不是页面局部组件**：跨中间页面切换仍保留当前任务详情及草稿；关闭后中间区域获得全部空间。不引入多标签面板、多个同时打开的 Inspector 或 AI 对话面板。
3. **右栏可拖拽**：初始维持 400px；拖动过程跟手、宽度持久化、窄窗口限制合理。先复用项目已有轻量布局能力；若实测不能可靠满足要求，再评估成熟面板库，而非为了依赖而增加依赖。
4. **Today / Task 使用同一 Activity 布局**：时间在正文上方，评论在下面，系统事件简洁单行，评论可原地编辑；无需重复的装饰性时间轴、头像、多人协作功能。
5. **Today 的任务评论额外显示任务上下文**：在**时间右侧**放**正常正文等级字号**的可点击任务标题，不刻意缩小或弱化；独立 Activity 不显示任务标题。Task 详情内因已有任务上下文，不重复显示链接。
6. **统一输入组件**：以 Task 详情现有的一体化输入框为基准，输入区与发送按钮处于同一容器；Today 仍占满原本可用宽度、保持在今日记录顶部；Task 详情输入框继续固定在底部。
7. **补齐编辑能力**：Today 与 Task 详情的人工 Activity 评论都支持原地编辑、保存/取消、`⌘+Enter`、`[[笔记引用]]`、离开草稿保护；任务完成、重新打开等系统事件只读。
8. **产品克制**：不新增 Activity 类型、不改变 Markdown 数据结构、不引入评论线程、用户头像、反应、状态工作流、AI 面板或多主导航。任务创建是否作为 Activity 属于独立语义议题，不借 UI 统一改数据。

## 交付结果

- 布局归属正确的三栏 Pata：单个可收起、可调整宽度的 Task Inspector。
- Today / Tasks / Tag / Notes 任务入口的导航与草稿保护一致。
- Today 与 Task 详情一致的 Activity 阅读、输入和编辑体验，Today 仅补充必要的任务上下文链接。
- 自动化构建与测试，以及 macOS WKWebView 实机回归。只有通过验收才标记完成。
