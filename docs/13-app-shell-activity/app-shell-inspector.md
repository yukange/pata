# Pata App Shell：应用级可收起任务详情栏

> 2026-10-21 阶段 13 架构裁决。此文档负责恢复最初约定的全局三栏布局，替换此前“Today/Tasks/Tag 页面各自持有固定详情栏”的实现。**PR #9 尚待构建、Review 与实机验收**；不引入新的导航入口或 Project 概念。

## 布局所有权

```text
App Shell
├── 左侧 Navigation（常驻）
└── 内容区域
    ├── Workspace（Today / Tasks / Notes / Tag）
    └── Inspector（可选，TaskDetailPanel）
```

- 三栏属于整个应用框架。Today、Tasks、Notes 和标签页都**只是中间工作区**，不再分别创建任务详情面板。
- App 统一持有 `detailSelection` 与单个 `TaskDetailPanel`；切换主区页面不销毁已打开的详情或其草稿。
- 点击任务，在同一个 Inspector 中打开；再次选择其他任务，先检查旧任务详情未保存内容。
- 关闭 Inspector 后释放空间，中间区域自然扩张；再次打开恢复上一次的用户设定宽度。
- 编辑 Notes 以及全局搜索打开任务，也复用同一右栏。设置页保持现有整页展示方式，返回后保留详情。

## 尺寸与交互

- 默认 400px，用户可拖拽主区与详情之间的分隔线；支持左右方向键微调。
- 持久化设置键 `pata_detail_panel_width`；合理范围 280–720px。窗口变窄时优先为主区保留约 320px。
- 拖动过程直接跟随鼠标，不加入过渡动画、额外工具条或伸缩按钮。
- 左侧 Navigation 的宽度与行为暂时维持现状。

## 数据与上下文保护

- App 统一负责 Inspector 的任务选择、关闭与打开前的未保存草稿确认。
- Today 仍管理其当前日期、日计划与 Activity 草稿；来自 Today 的任务带可选的日期上下文，使“移出今日/当日计划”继续可用。
- Today 切换日期时，如果当前 Inspector 的计划上下文已经不适用则移除该上下文，不隐式关闭任务。
- 主区继续分别处理自身未保存草稿；跨页切换不因 Inspector 存在而丢失草稿。
- 任务状态、评论写入、删除以及计划移除后刷新相关页面；切换 Vault 时重置选中任务并保护未保存草稿。
- Go Core API / Activity ID / Markdown 文件格式不变。

## 范围

这是 013-001/002 的布局和状态所有权纠偏，不是重新设计任务/笔记功能。013-003/004/005 的 Activity 展示、原地编辑与 Composer 统一见 [proposal.md](proposal.md)，需在独立 PR 中实现，均不改 Activity 存储逻辑。

## 验收场景

1. 分别从 Today、Tasks、标签页、搜索和 Notes 的任务引用打开任务，确认都显示在同一个右栏。
2. 右栏打开后切换 Today、Tasks、Notes，确认右栏不会因页面切换而重建。
3. 任务详情保留未保存草稿时打开另一任务，取消确认应继续编辑原任务。
4. 在 Today 打开当天计划任务，确认“移出今日计划”生效；切换日期后不出现过期的计划操作。
5. 手动关闭右栏，中间区充满可用空间；重新打开仍使用之前调整的宽度。
6. 窄窗口、浅/深色模式下拖拽与键盘微调正确，鼠标释放后不会残留 resize 光标。
7. 从任务引用进入 Notes 并返回来源、任务状态修改、删除和切换 Vault 均不发生丢稿、重复详情或旧 Vault 数据遗留。
