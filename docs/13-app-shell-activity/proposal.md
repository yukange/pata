# 阶段 13 · App Shell 与 Activity 体验统一 — Proposal

> 状态：**代码实现与验收已完成**（2026-10-22）。阶段 12 是已完成历史阶段；本阶段解决最初三栏架构的实现偏差及 Activity UI 不一致。本文是 **013 的实施与验收主文档**；App Shell 细节见 [app-shell-inspector.md](app-shell-inspector.md)。

## 一、边界与基线

- 设计原则：Less is more、个人真实使用体验优先；只恢复既定架构与统一现有 Activity 交互，不扩展业务语义。
- 维持三主入口 Today / Tasks / Notes，Tag 仍是标签聚合视图。
- 保留阶段 12 的视觉、Design Tokens、系统强调色原则、Lucide、现有 `[[笔记引用]]` 及 Markdown / Go Core API。
- 不改变 Notes 单列瀑布浏览与笔记编辑行为；不引入新的 AI/Agent UI、Project、多 Inspector 或完整通用面板管理平台。
- 013 和 012 的职责清晰分开：**012 已完成并冻结，013 从本阶段开始验收**。PR #9 是 013 的第一批实施，并非 012 的追加验收。

## 二、应用级三栏架构（013-001）

```text
Pata App Shell
├── Navigation（左侧，常驻）
├── Workspace（中间，当前 Today / Tasks / Notes / Tag）
└── Inspector（右侧，可选，当前只承载 TaskDetailPanel）
```

- App 层持有右栏的任务选择、展开/关闭、草稿确认、布局尺寸、持久化宽度。
- Today / Tasks / Tag 不再自行创建 `TaskDetailPanel` 或包裹独立 `DetailSplit`，仅负责 Workspace 内容与本页事件。
- 当前任务跨中间页面切换不应被卸载、替换或丢稿。打开新任务之前使用现有 `confirmLeave`；关闭右栏恢复主区空间与必要的焦点。
- Today 的所选日期/日计划上下文仍归 Today 管理，并在从 Today 打开任务时按需传入 Inspector；移出当天计划、修改任务状态、删除任务和跨页更新均需保持原行为。
- 从任务详情打开 Note、返回任务，以及 Notes/搜索中直接打开任务，统一使用 App 的任务打开入口。
- 设置仍可沿用现有全主区视图，不因此设计通用多面板路由。

## 三、可调宽度（013-002）

- 默认宽 400px，可调整范围建议 280–720px，窗口较窄时尽量保障主区约 320px；若窗口比两区可用下限之和还窄，不允许无交互空间的重叠。
- 主区和右栏之间的分隔线为拖拽热区，Pointer 跟手、不使用跳格式重排或过渡动画；方向键可微调，键盘焦点可见。
- 调整后保存到应用本地偏好；三主入口和标签视图共用一份宽度，不为每个页面单独存。
- 收起后主区自动填满，重新展开恢复用户调整宽度；浅色/深色与窗口缩放中无跳动或光标残留。
- 复用现有布局实现，真实存在性能/可访问性问题才评估 `react-resizable-panels`，禁止同时维护两套尺寸状态。

## 四、Activity 展示统一（013-003）

Today 和 Task 详情的 Activity 行共用同一组视觉与交互规则，可提取 `ActivityItem` 或等价的共享组件，但不要求制造泛化配置框架。

| 元素 | Today | Task 详情 |
| --- | --- | --- |
| 时间 | 正文上方，展示时分（当日已有日期） | 正文上方，跨天展示日期与时分 |
| 任务评论上下文 | **时间右侧**展示任务标题链接，字号和正文为同等级，不刻意变小 | 不重复任务标题 |
| 无任务关联的独立 Activity | 只展示时间、正文 | 不涉及 |
| 人工评论 | 时间下方正文，悬停显示编辑入口 | 同样结构、同样编辑入口 |
| 系统状态事件 | 完成 / 重新打开等单行且只读 | 同样结构 |
| 排序 | 维持现有时间语义，不借展示改动重排 | 同左 |

- 任务链接可点击打开 App 级右侧详情；正常文字尺寸，标题较长时优先允许合理换行，避免丢失上下文，编辑按钮保持可用。
- 保持低视觉噪音；不新增左侧时间列、类型图标专属列、头像、装饰性纵线、评论回复线程或反应。
- 同一 Activity 在两个页面中的正文、笔记引用、编辑结果一致；不复制数据。

## 五、Composer 与原地编辑统一（013-004/005）

### ActivityComposer

- 以任务详情现有结构为基准：**输入区与发送按钮位于同一轻量圆角容器**，发送按钮在容器右下角。
- **Today 保持原有整体可用宽度**，不缩短、不右移、不为对齐活动正文额外缩进；入口继续位于今日记录顶部。
- Task 详情输入区仍固定在右栏底部；两个页面共享边框、圆角、焦点、按钮、错误反馈、发送状态与快捷键行为。
- 两端保留 `[[笔记引用]]`、`⌘+Enter` 提交、IME 组合输入保护、空值禁用与失败保留草稿。
- 通过传入业务回调、占位文案和 refs 数据复用同一个组件，不在 Composer 内复制持久化业务逻辑。

### ActivityEditor

- 复用已有后端 `VaultService.UpdateActivity`；不新加后端接口或修改 Markdown 协议。
- 为 Task 详情人工评论补齐悬停编辑、原地修改、保存/取消、快捷键和 `[[笔记引用]]`；Today 既有编辑能力迁移/复用后不能回退。
- 编辑区在原正文处出现，保存/取消按钮就地呈现，切换页面/任务/关闭侧栏时保护未保存的编辑草稿。
- 仅人工 Activity 可以编辑；完成、重新打开等自动事件必须保持只读。
- 成功后更新 Today/Task 各自视图；冲突/保存失败时不清空草稿、不展示虚假的成功状态。
